❌ Failures & Issues (most severe first)

Highverified Excessive page weight & slow load times Performance §1.1
The Why i2V page transfers 12–15 MB (≈16 MB decoded) — almost all of it images across ~107 image requests. Home pulls 250 resources. Heaviest assets are full-resolution WebP images.
Live evidence: the heavy page was re-confirmed on every engine — Chromium 14.85 MB, Firefox 12.62 MB, WebKit 13.41 MB. Top images by size: scalable-ai-powered-img-2.webp 1.58 MB, temper-proof-audit-logs.webp 1.35 MB, multi-level-permissions.webp 1.31 MB, system-hardening.webp 1.28 MB.
Fix: resize/recompress oversized images, add responsive srcset, lazy-load below-the-fold images and the YouTube/Maps embeds (load on interaction), and put assets behind a CDN with far-future caching.
Highrefined Broken footer "terms" link on sub-pages (404) Links §1.2
The footer "terms of service" link uses a relative href without a leading slash (terms-of-use), so it resolves under the current path and 404s on every sub-page. The correct target /terms-of-use/ returns 200.
Live status codes: /terms-of-use/ → 200 · /products/terms-of-use → 404 · /products/video-management-software/terms-of-use → 404.
Correction: the link text is "terms of service" (not "Terms of Use"), and the footer is inconsistent — one instance correctly uses absolute /terms-of-use/ while the repeated instances use the bare relative path. The root cause (missing leading slash) is exactly as reported.
Fix: change every instance of the href to the absolute /terms-of-use/.
Highverified Hundreds of images missing alt text Accessibility §2.4
Home: 401 of 575 images (~70%) have empty/missing alt; Why i2V: 173 of 310. Of Home's 401, 282 are non-SVG (likely meaningful content images). Some decorative SVG icons legitimately use alt="".
Live evidence: counted 575 images on Home, 401 with missing/empty alt — an exact match to the original audit.
Fix: add descriptive alt to meaningful images; explicit alt="" on purely decorative ones.
Mediumverified Unusable on real mobile networks Mobile §4
Home page, throttled: 4G = 12.5 s load · Fast 3G = 57.3 s · Slow 3G = timeout > 90 s. Same root cause as page weight — the 12+ MB image payload was re-confirmed live on all three engines, making these figures directly attributable.
Fix: resolve page weight (above); prioritize critical-path rendering and defer heavy media.
Mediumverified Slow server response (TTFB ~1.3–1.9 s) Performance §1.1
Re-measured live: Home TTFB 1.5 s, Why i2V 1.4 s (Apache/WordPress, no edge caching evident), delaying everything downstream. Contact spiked to ~2.9 s on Firefox.
Fix: add server/page caching, object cache, and a CDN in front of origin.
Mediumverified Email link missing mailto: & broken resource link (404) Links §1.2
An email address is used as a normal link without the prefix — /contact-us/mandeep.panwar@i2vsys.com (404). A resource download is broken — /resources/i2v-vms-pre-installer-1/ (404).
Live status codes: both returned 404.
Fix: prefix the email with mailto:; repoint or remove the dead resource link.
Mediumverified Missing semantic landmarks (<main>, <footer>) Accessibility §2.4
Header & nav exist, but no <main> and no <footer> element — confirmed on both Home and Why i2V — so screen-reader landmark navigation suffers.
Live evidence: main=0, footer=0, header=1, nav=1; no role="main"/role="contentinfo" fallback either.
Fix: wrap primary content in <main> and use a real <footer> element.
Mediumnot reproduced Keyboard focus indicator Accessibility §2.4
Reported as a suppressed focus ring (0 px outline). On re-test, the main navigation links showed the browser's default visible focus ring, so a blanket "suppressed focus" claim does not hold.
Live evidence: focusing the "Home" nav link gives computed outline-width: 2px; outline-style: auto.
Re-scoped: treat this as inconsistent focus styling — verify per-component (some styled buttons may still lack a ring) rather than a site-wide suppression.
Fix: audit styled buttons/CTAs individually and ensure a clear :focus-visible outline/box-shadow everywhere.
Mediumverified Mobile menu toggle is not a semantic button Mobile / A11y §4
The hamburger (☰) is visibly present on mobile, but it is not a <button> and lacks aria-expanded — fine for touch/mouse but not keyboard/AT-friendly.
Live evidence (390px viewport): header <button> count = 0; the visible toggle is a <div> with no role, aria-expanded, or tabindex.
Fix: convert the toggle to a <button> with aria-expanded/aria-controls.
Lowverified Inconsistent brand capitalization Content §1.5
Mixed forms appear: "i2V systems" (lowercase systems) ×3 vs "i2V Systems" ×1 in visible Home copy; i2V ×34. No placeholder/lorem text found.
Fix: standardize on one form (e.g. "i2V Systems").
Lowverified Two <h1> elements on Home SEO/A11y §2.4
Home has 2× <h1> — "Integrated solutions…" and "Video"; there should be exactly one. (The Why i2V page correctly has a single h1.)
Lowverified No skip-to-content link Accessibility §2.4
No skip link present; the first focusable items are empty javascript:void(0) links, so keyboard users cannot bypass the nav.
Lowverified reCAPTCHA 401 console noise in Safari/WebKit Cross-browser §3
Engine-specific 401s from google.com/recaptcha/api2/pat under WebKit — known reCAPTCHA telemetry behavior; cosmetic, forms still work. Re-confirmed live: 4–5 such errors per page in WebKit, while Chromium loads clean.
Lowverified YouTube cookie SameSite warnings in Firefox Cross-browser §3
Embedded video on Why i2V triggers benign third-party __Secure-YEC cookie warnings in Firefox — re-confirmed live (2 warnings on that page only).
Lowverified Minimal Content-Security-Policy & missing form attributes Security/Forms §1.4/1.6
No CSP <meta> present; policy is header-only and thin (upgrade-insecure-requests) — Firefox also logs a report-only CSP notice on Home. Contact-form visible fields lack HTML5 required/aria-required and autocomplete hints (enforcement relies on server-side CF7).
Fix: add a fuller CSP; add required/autocomplete to mandatory contact fields for instant feedback.

ℹ️ Testing Limitations

  • WebKit is the Safari rendering engine but not native macOS/iOS Safari hardware; devices are emulated (viewport/DPR/touch/UA), not physical phones/tablets.
  • 3G/4G figures use network emulation, not real cellular radios; these rows are carried from the original run and were not re-throttled this session.
  • Forms were validated client-side and inventoried, but not submitted end-to-end to avoid live leads / tripping reCAPTCHA.
  • Image alt counts include intentionally-decorative images (alt=""); the true "missing meaningful alt" figure is lower than 70% (≈282 non-SVG on Home).
  • Load-event timings reflect live network conditions on 2026-06-02 and will vary run to run.
