Impact & Reproduction Guide — i2vsys.com
For each finding: what happens if it is left unfixed, and exact steps to reproduce it.
Date: 2026-06-02 Site: https://www.i2vsys.com/ Companion to: Final Website Test Report
Each card below has two parts — ⚠ If this persists (the business/technical consequence of not fixing it) and 🔁 Steps to reproduce (manual, browser-only steps anyone can follow). Reproduction uses only a standard browser and its built-in Developer Tools (F12) — no special software required. A green Expected result line states what you should observe if the issue is present.
🔴 High 🟠 Medium 🟡 Low

🔴 High-Severity Issues

High Excessive page weight (Why i2V ≈ 12–15 MB) Performance

⚠ If this persists

  • Lost visitors & leads: a 12–15 MB page can take 18–58 s on 3G/4G; most users abandon after ~3 s, so demo/contact conversions drop.
  • SEO ranking penalty: Core Web Vitals (LCP) stay poor, lowering Google ranking and organic traffic over time.
  • Higher bandwidth cost & server load for both the visitor (mobile data) and the origin server.
  • Worse on slower engines: the same page took ~27.8 s to load in Safari/WebKit vs ~4.9 s in Chrome — Safari/iPhone users suffer most.

🔁 Steps to reproduce

  1. Open https://www.i2vsys.com/why-choose-i2v/ in Chrome.
  2. Press F12 → open the Network tab.
  3. Tick Disable cache, then reload the page (Ctrl+R).
  4. Read the summary bar at the bottom: “… transferred” total and request count.
  5. Sort the list by the Size column to see the heaviest images.
Expected result: total transfer ≈ 12–15 MB; several .webp images ≈ 1.3 MB each (e.g. multi-level-permissions.webp, system-hardening.webp).
High Broken footer “terms of service” link on sub-pages (404) Links

⚠ If this persists

  • Legal exposure: visitors on most pages cannot reach the Terms of Use, weakening the enforceability of site terms.
  • Broken trust: a 404 on a legal/footer link looks unprofessional and erodes credibility for a security vendor.
  • SEO: repeated 404s across many pages waste crawl budget and can be flagged in Search Console.

🔁 Steps to reproduce

  1. Open any sub-page, e.g. https://www.i2vsys.com/products/.
  2. Scroll to the footer and click “terms of service”.
  3. Observe the URL it navigates to and the page shown.
  4. Compare with the correct page: open https://www.i2vsys.com/terms-of-use/ directly.
Expected result: the footer link goes to /products/terms-of-use → 404 Not Found, while /terms-of-use/ loads fine (200). Root cause: the href is the relative terms-of-use (no leading slash).
High Hundreds of images missing alt text Accessibility

⚠ If this persists

  • Screen-reader users excluded: meaningful images are announced as “image” or skipped, making content inaccessible.
  • Legal/compliance risk: fails WCAG 2.1 §1.1.1 — relevant for ADA / EN 301 549 / accessibility procurement requirements.
  • Lost image SEO: search engines can’t index images without alt text, reducing image-search traffic.

🔁 Steps to reproduce

  1. Open https://www.i2vsys.com/ and press F12 → Console tab.
  2. Paste and run:
    document.querySelectorAll('img').length
  3. Then run:
    [...document.querySelectorAll('img')].filter(i=>!i.alt.trim()).length
Expected result: ≈ 575 total images and ≈ 401 with empty/missing alt (~70%).

🟠 Medium-Severity Issues

Medium Unusable on real mobile networks Mobile

⚠ If this persists

  • Mobile visitors bounce: ~57 s on Fast-3G / timeout on Slow-3G means many phone users never see the content.
  • Mobile is typically the majority of traffic — this directly suppresses leads from the largest segment.
  • Compounds the page-weight and SEO problems above for the worst-connected users.

🔁 Steps to reproduce

  1. Open https://www.i2vsys.com/ in Chrome → F12 → Network tab.
  2. In the Throttling dropdown choose “Fast 3G” (or “Slow 3G”).
  3. Tick Disable cache and reload; watch the Load time in the status bar.
Expected result: Fast 3G ≈ 57 s load; Slow 3G times out (> 90 s).
Medium Slow server response (TTFB ~1.3–1.9 s) Performance

⚠ If this persists

  • Everything starts late: a slow first byte delays rendering on every page, hurting perceived speed and Core Web Vitals.
  • Indicates no edge/page caching — the site is vulnerable to traffic spikes and slower for distant visitors.

🔁 Steps to reproduce

  1. Open any page → F12 → Network tab → reload.
  2. Click the first (document) request → Timing sub-tab.
  3. Read “Waiting for server response (TTFB)”.
Expected result: TTFB ≈ 1.3–1.9 s (occasionally higher), well above the < 0.8 s “good” threshold.
Medium Email used as link without mailto: + broken resource link (404) Links

⚠ If this persists

  • Dead contact path: clicking the email leads to a 404 instead of opening the mail client — a lost sales/contact opportunity.
  • Broken download: the dead resource link frustrates prospects trying to get the VMS pre-installer.
  • Both add 404s that look unprofessional and hurt SEO crawl quality.

🔁 Steps to reproduce

  1. Visit the Contact page and click the mandeep.panwar@i2vsys.com link (or open https://www.i2vsys.com/contact-us/mandeep.panwar@i2vsys.com).
  2. Open the resource link https://www.i2vsys.com/resources/i2v-vms-pre-installer-1/ directly.
Expected result: both return 404 Not Found. The email should instead use mailto: and open the mail app.
Medium Missing semantic landmarks (<main>, <footer>) Accessibility

⚠ If this persists

  • Harder screen-reader navigation: assistive tech relies on landmarks to jump to main content / footer; without them users must tab through everything.
  • Contributes to WCAG non-conformance and a lower automated accessibility score.

🔁 Steps to reproduce

  1. Open https://www.i2vsys.com/ → F12 → Console.
  2. Run: document.querySelectorAll('main').length
  3. Run: document.querySelectorAll('footer').length
Expected result: both return 0 (no <main> / <footer>), and there is no role="main"/role="contentinfo" fallback.
Medium Inconsistent keyboard focus styling (verify per-component) Accessibility

⚠ If this persists

  • Keyboard users get lost: if any interactive control lacks a visible focus ring, sighted keyboard/AT users can’t tell where they are.
  • Risks WCAG 2.4.7 (Focus Visible) failures on the affected components.
  • Note: the main nav links do show a focus ring, so this is a targeted check, not a site-wide gap.

🔁 Steps to reproduce

  1. Open any page and click once in an empty area, then press Tab repeatedly.
  2. Watch each focused element (links, buttons, form fields, CTAs) for a visible outline/ring.
  3. For a suspect element, inspect it (F12) and check the computed outline / box-shadow on :focus.
Expected result: nav links show a 2px ring (good); flag any styled button/CTA whose computed outline-width is 0px with no box-shadow.
Medium Mobile menu toggle is not a real <button> Mobile / A11y

⚠ If this persists

  • Keyboard/AT users can’t open the menu: a non-button <div> isn’t focusable or operable by Enter/Space, and screen readers don’t announce it as a toggle.
  • No aria-expanded means assistive tech can’t tell whether the menu is open or closed.
  • WCAG 4.1.2 (Name, Role, Value) failure on mobile navigation.

🔁 Steps to reproduce

  1. Open https://www.i2vsys.com/ → F12 → toggle the device toolbar (Ctrl+Shift+M) and pick a phone (≈390px).
  2. Right-click the hamburger (☰) → Inspect; check the element’s tag and attributes.
  3. In the Console run: document.querySelector('header').querySelectorAll('button').length
Expected result: the toggle is a <div> (not <button>) with no role/aria-expanded/tabindex; header button count = 0.

🟡 Low-Severity Issues

Low Inconsistent brand capitalization Content

⚠ If this persists

  • Weaker brand consistency: mixing “i2V systems” and “i2V Systems” looks careless and dilutes brand identity.

🔁 Steps to reproduce

  1. On the Home page, press F12 → Console.
  2. Run: (document.body.innerText.match(/i2V systems/g)||[]).length and (document.body.innerText.match(/i2V Systems/g)||[]).length
Expected result: both forms appear (≈ 3 lowercase “systems” vs 1 “Systems”).
Low Two <h1> elements on Home SEO / A11y

⚠ If this persists

  • Diluted SEO signal: multiple h1s muddy the page’s primary topic for search engines.
  • Slightly confuses screen-reader heading navigation.

🔁 Steps to reproduce

  1. Open Home → F12 → Console.
  2. Run: document.querySelectorAll('h1').length then [...document.querySelectorAll('h1')].map(h=>h.innerText)
Expected result: count = 2 (“Integrated solutions…” and “Video”).
Low No skip-to-content link Accessibility

⚠ If this persists

  • Slower keyboard navigation: users must tab through the whole nav on every page to reach content.
  • Best-practice WCAG 2.4.1 (Bypass Blocks) gap.

🔁 Steps to reproduce

  1. Open any page and immediately press Tab once from the very top.
  2. Observe whether a “Skip to content” link appears as the first focusable item.
Expected result: no skip link appears; the first focusable items are empty javascript:void(0) links.
Low reCAPTCHA 401 console noise in Safari/WebKit Cross-browser

⚠ If this persists

  • Mostly cosmetic: forms still work, but the console errors can mask real issues during debugging and look untidy.

🔁 Steps to reproduce

  1. Open any page in Safari (or a WebKit-based browser) → open the Web Inspector → Console.
  2. Reload and watch the console.
Expected result: 4–5 entries of “Failed to load resource: … 401” from recaptcha/api2/pat per page. Chrome shows none.
Low YouTube cookie SameSite warnings in Firefox Cross-browser

⚠ If this persists

  • Benign: third-party YouTube embed cookies are flagged; no functional impact, but adds console noise in Firefox.

🔁 Steps to reproduce

  1. Open https://www.i2vsys.com/why-choose-i2v/ in Firefox → F12 → Console.
  2. Reload and look for cookie warnings.
Expected result: ≈ 2 warnings about the __Secure-YEC cookie being rejected (SameSite / cross-site).
Low Minimal CSP & missing form attributes Security / Forms

⚠ If this persists

  • Weaker XSS defense: a thin Content-Security-Policy provides little protection against injected scripts.
  • Worse form UX: missing required/autocomplete means no instant client-side feedback or browser autofill.

🔁 Steps to reproduce

  1. CSP: open F12 → Network → click the document request → Headers → look for content-security-policy.
  2. Form: on the Contact page, right-click a required field → Inspect and check for required / autocomplete attributes.
Expected result: CSP is only upgrade-insecure-requests (or absent as a meta tag); contact fields lack required/autocomplete.
